# 0004. Resultのコンストラクタはprivate protectedにする

## ステータス

Accepted

## コンテキスト

`Result`のコンストラクタは、生成時に不変条件(成功ならError.None、失敗なら
Error.Noneでないこと)を検証しているため、この検証を経ずにインスタンスを
作れてしまう経路を残したくない。一方で、同一アセンブリ内の`Result<T>`は
基底クラスの初期化ロジックを呼ぶ必要があるため、コンストラクタを完全に
`private`にすることはできない。

当初`protected`にしていたが、これは「別アセンブリからでも継承さえすれば
呼び出せる」ため、利用者が独自に`Result`を継承してカスタムResultを作る
余地を残してしまっていた。この継承は想定しておらず、`Result<T>`という
このライブラリ内の特定のサブクラスのためだけにコンストラクタを開放したい。

## 検討した選択肢

- **`protected`のまま**: 同一アセンブリ・別アセンブリを問わず、継承さえ
  すればコンストラクタを呼べる。今回のような「特定の1サブクラスのためだけに
  開放したい」という意図には広すぎる。

- **`internal`にする**: 同一アセンブリ内であれば、継承していない任意の
  クラスからもアクセス可能になる。継承と無関係にアクセスを許してしまうため、
  「不変条件の検証を必ず通す」という目的には合わない。

- **`protected internal`にする**: 「同一アセンブリ内」または「継承先」の
  どちらか一方を満たせばアクセス可能(OR条件)。別アセンブリからの継承であっても
  アクセスできてしまうため、外部からの継承を防ぎたいという意図に反する。

- **`private protected`にする**: 「同一アセンブリ内」かつ「継承先」の
  両方を満たす場合のみアクセス可能(AND条件、C# 7.2以降)。同一アセンブリ内の
  `Result<T>`だけがコンストラクタを呼べ、外部からの継承では呼び出せない
  (呼び出そうとするとコンパイルエラーになる)。

## 決定

`private protected`を採用する。

「`Result<T>`という、このライブラリ自身が提供する1つのサブクラスのため」に
限定してコンストラクタを開放するという意図を、最も正確に表現できるアクセス
修飾子である。

## 結果・トレードオフ

- 利用者が別アセンブリから`Result`を継承しても、コンストラクタを呼び出せず
  コンパイルエラーになるため、意図しない継承が実質的に不可能になる。
- 同一アセンブリ内であっても、`Result<T>`以外の継承先を追加したくなった場合は
  そのままアクセスできるため、ライブラリ内部での将来的な拡張は妨げない。
- `sealed`のような完全な継承禁止ではないため、コード上「継承してよいのは
  同一アセンブリ内のみ」という制約はコメントやXMLドキュメントで補足している。
